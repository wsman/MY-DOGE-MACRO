# WF-ANALYZE: 规划一致性校验工作流

**版本**: v1.4.0  
**协议类型**: T2-工作流协议  
**触发**: State B → State C 执行前  
**模式**: 只读分析

---

## 1. 目标

在进入 State C 执行阶段前，自动检测 DS-050、DS-051、DS-052 之间的逻辑矛盾、遗漏和不一致。

## 2. 执行步骤

### Step 1: 加载上下文
| 文档 | 路径 | 用途 |
|------|------|------|
| DS-050 | `memory_bank/standards/DS-050_*.md` | 功能需求 |
| DS-051 | `memory_bank/standards/DS-051_*.md` | 架构设计 |
| DS-052 | `memory_bank/standards/DS-052_*.md` | 原子任务 |
| T1 Axioms | `memory_bank/axioms/*.md` | 架构约束 |

### Step 2: 检测分析
- **重复检测**: 识别相似需求
- **模糊检测**: 标记缺少量化标准的形容词
- **欠规范检测**: 缺少验收标准的需求
- **宪法对齐**: 违反 T1 约束的条目标记为 CRITICAL
- **覆盖缺口**: 零任务覆盖的需求
- **不一致检测**: 术语漂移、数据实体矛盾

### Step 3: 生成报告
输出分析报告，包含：
- CRITICAL: 必须修复
- WARNING: 建议修复
- INFO: 参考信息
