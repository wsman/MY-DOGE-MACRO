# MY-DOGE-MICRO 项目核心原则与公理

## A. 架构公理 (Architectural Axioms)

### 1. 三明治架构原则 (Sandwich Architecture Principle)
- **分层设计**: Rust (系统层) + Python (逻辑层) + React (UI层) 三层严格分离
- **职责划分**: 
  - Rust: 系统资源管理、进程调度、安全沙箱
  - Python: 量化分析、数据清洗、AI推理
  - React: 用户交互、状态管理、可视化渲染
- **通信协议**: 使用Tauri IPC + HTTP API进行跨层通信

### 2. 本地优先原则 (Local-First Principle)
- **数据主权**: 所有用户数据本地存储，无云端依赖
- **隐私保护**: 敏感数据不离开用户设备
- **离线可用**: 核心功能支持离线运行
- **增量同步**: 支持选择性数据云端备份

### 3. 绞杀榕策略 (Strangler Fig Strategy)
- **渐进迁移**: 逐步替换遗留代码，避免一次性重写
- **功能解耦**: 将系统分解为独立可替换的微服务
- **并行运行**: 新旧系统可并行运行，确保平稳过渡
- **测试驱动**: 每个迁移步骤都有完备的测试覆盖

## B. 技术规范 (Technical Specifications)

### 4. 列式传输协议 (Columnar Transmission Protocol)
- **数据格式**: API响应必须使用 `{columns: [...], data: [...]}` 格式
- **性能优化**: 优先使用split格式而非records格式
- **类型提示**: 列定义包含数据类型和描述信息
- **压缩支持**: 支持gzip/brotli压缩以减小传输体积

### 5. 全链路握手协议 (Full-Chain Handshake Protocol)
- **动态端口分配**: Rust启动时动态分配Python服务端口
- **认证令牌**: 注入唯一认证token保护API安全
- **进程监控**: Python服务监控父进程状态，自动优雅退出
- **健康检查**: 定期心跳检测确保服务可用性

### 6. 防幻觉机制 (Anti-Hallucination Mechanism)
- **实时校准**: AI分析必须联网获取实时数据进行校准
- **数据引用**: 所有分析结论必须明确引用数据来源
- **交叉验证**: 多数据源交叉验证关键信息
- **缓存策略**: 智能缓存减少重复网络请求

## C. 开发原则 (Development Principles)

### 7. 性能优先原则 (Performance-First Principle)
- **前端优化**: 虚拟滚动(react-virtuoso)、代码分割、图片懒加载
- **后端优化**: 向量化计算、连接池、查询缓存
- **内存管理**: 及时释放大对象，避免内存泄漏
- **并发控制**: 合理使用线程池和异步IO

### 8. 类型安全原则 (Type Safety Principle)
- **TypeScript**: 严格模式(strict mode)，完整类型定义
- **Python**: 全面使用类型提示(type hints)
- **数据验证**: Pydantic模型验证所有API输入输出
- **运行时检查**: 关键路径添加运行时类型检查

### 9. 可序列化布局 (Serializable Layout)
- **布局持久化**: UI布局状态可保存、恢复、导出、导入
- **默认布局**: 提供精心设计的默认布局方案
- **用户定制**: 支持用户自定义布局并持久化
- **快捷键**: 标准化布局操作快捷键(Ctrl+Shift+S/R)

## D. 量化分析原则 (Quantitative Analysis Principles)

### 10. 数据引用规则 (Data Citation Rule)
- **引用格式**: 所有分析结论必须使用 `[数据: 指标名称 数值]` 格式
- **明确来源**: 明确标注数据来源和时间范围
- **避免模糊**: 禁止使用"可能"、"大概"等模糊表述
- **数字精度**: 保持合理的数字精度，避免虚假精确

### 11. RSRS趋势强度指标 (RSRS Trend Strength Indicator)
- **定义**: RSRS = R² × sign(Slope)，范围-1.0到1.0
- **解读**:
  - RSRS > 0.8: 极强上涨趋势
  - 0.5 < RSRS ≤ 0.8: 中等上涨趋势
  - -0.5 ≤ RSRS ≤ 0.5: 震荡或无趋势
  - -0.8 ≤ RSRS < -0.5: 中等下跌趋势
  - RSRS < -0.8: 极强下跌趋势
- **计算窗口**: 默认18个交易日(约一个月)

### 12. VolSkew风险指标 (Volatility Skew Risk Indicator)
- **定义**: VolSkew = σ(5日) / σ(20日)
- **解读**:
  - VolSkew < 0.8: 市场极度平静，可能是变盘节点
  - 0.8 ≤ VolSkew ≤ 1.5: 正常波动区间
  - VolSkew > 1.5: 风险释放中，短期波动加剧
- **预警**: VolSkew异常值时触发风险预警

## E. 错误处理规范 (Error Handling Standards)

### 13. 统一错误响应 (Unified Error Response)
- **格式**: `{"error": {"code": "ERROR_CODE", "message": "用户友好信息", "details": {}}}`
- **HTTP状态码**: 正确使用HTTP状态码(400,401,403,404,429,500等)
- **错误分类**: 输入错误、认证错误、业务错误、系统错误
- **日志记录**: 错误发生时记录详细上下文信息

### 14. 优雅降级 (Graceful Degradation)
- **缓存兜底**: API失败时返回缓存数据
- **功能降级**: 高级功能不可用时提供基础功能
- **用户提示**: 明确告知用户功能受限原因
- **自动恢复**: 网络恢复后自动重试失败操作

### 15. 监控告警 (Monitoring and Alerting)
- **性能监控**: 记录API响应时间、内存使用、CPU负载
- **业务监控**: 关键业务指标(扫描成功率、分析准确率)
- **错误告警**: 严重错误时触发通知
- **健康检查**: 定期系统自检并报告状态

## F. 安全规范 (Security Standards)

### 16. 认证授权 (Authentication & Authorization)
- **令牌认证**: 使用Bearer token进行API认证
- **权限控制**: 基于角色的访问控制(RBAC)
- **会话管理**: 安全的会话管理和过期机制
- **敏感数据**: API密钥等敏感数据加密存储

### 17. 输入验证 (Input Validation)
- **白名单验证**: 所有用户输入进行白名单验证
- **SQL注入防护**: 使用参数化查询，禁止拼接SQL
- **XSS防护**: 输出编码防止跨站脚本攻击
- **文件上传**: 严格限制上传文件类型和大小

## G. 部署运维 (Deployment & Operations)

### 18. 构建打包 (Build & Packaging)
- **跨平台支持**: Windows/macOS/Linux全平台支持
- **安装包大小**: 控制安装包体积，使用增量更新
- **依赖管理**: 精确锁定依赖版本确保可重现构建
- **签名验证**: 发布包进行数字签名验证

### 19. 配置管理 (Configuration Management)
- **环境分离**: 开发/测试/生产环境配置分离
- **敏感配置**: 敏感配置不写入版本控制系统
- **热重载**: 支持配置热重载无需重启服务
- **配置验证**: 启动时验证配置有效性
